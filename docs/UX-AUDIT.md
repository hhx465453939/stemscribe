# UX 审计 · Stemscribe v0.2

> 审计方式：按**真实用户旅程**逐步走一遍代码路径，而不是看端点是否存在。
> 判据：一个从没用过这个软件的人，能否在**不看文档**的情况下完成这段旅程。
> 结论只写实测事实，不写愿望。

---

## 1. 旅程 A：第一次把一个视频转成文字

| # | 用户动作 | 现在的真实情况 | 痛感 |
|---|---|---|---|
| A1 | 打开软件 | 能开（窗口或浏览器） | — |
| A2 | 找到「新建任务」 | 在首页 | — |
| A3 | 选一个视频 | 只能**手打绝对路径**；无浏览按钮，无拖入 | 🔴 极高 |
| A4 | 选输出到哪 | **完全没有这个选项**。产物固定落在 `workdir/libraries/local-<hash>/`，名字是哈希，用户既不能指定也猜不到 | 🔴 极高 |
| A5 | 选模型 | 不能选。界面无法指定 whisper-tiny/base/…，只能靠改 `settings.json` | 🟠 高 |
| A6 | 调参数（语言等） | 参数页可改，但**改了不生效**：`NewTask` 提交时 `params: {}`，运行永远用引擎默认 | 🔴 极高（且是假承诺） |
| A7 | 点开始 | 有进度了（CHG-0010 已修） | — |
| A8 | 等的时候想取消 | **不能取消**。后端支持 `context` 取消，但没有端点也没有按钮 | 🟠 高 |
| A9 | 跑完了，想看产物 | 显示产物目录文字 + 复制路径。**不能一键打开文件夹** | 🟠 高 |
| A10 | 想知道用的是哪个模型/参数 | 产物 `meta.json` 里有，但界面不显示 | 🟡 中 |

**A 段结论**：能跑通，但 A3/A4/A6 三处任意一处都会让普通用户卡住。A6 最严重——它不是缺失，是**界面在说谎**。

## 2. 旅程 B：一次处理一批视频

| # | 用户动作 | 现在的真实情况 | 痛感 |
|---|---|---|---|
| B1 | 一次给几个文件 | 后端队列**已就绪**（`/api/queue`），但**前端还没接**，界面上仍然只有单输入框 | 🔴 极高 |
| B2 | 自动跑完一批 | 后端支持串行自动衔接；前端没有对应视图 | 🟠 高 |
| B3 | 撤掉排错的一个 | 后端有 `DELETE /api/queue/{id}`；界面无入口 | 🟡 中 |

**B 段结论**：能力已在后端，缺的是最后一公里。这是**白做的浪费**，因为用户看不到。

## 5. 旅程 E：资料库

| # | 用户动作 | 现在的真实情况 | 痛感 |
|---|---|---|---|
| E1 | 看做过哪些 | 真实列表（含段数、时长、状态） | — |
| E2 | 打开某一集看逐字稿 | **不能**。列表只读，点了没反应 | 🔴 极高 |
| E3 | 打开产物目录 | 不能 | 🟠 高 |
| E4 | 删掉不要的 | 不能 | 🟡 中 |
| E5 | 重跑某一集 | 不能（需回新建任务手动再来） | 🟡 中 |

**E 段结论**：资料库现在是**只能看不能进**，等于一个报表而不是工作区。

## 6. 全局

| 项 | 现状 | 痛感 |
|---|---|---|
| 长任务完成提醒 | 无系统通知；用户得盯着 | 🟠 高 |
| 错误日志入口 | 写在 `workdir/logs/engine.log`，界面无链接 | 🟠 高 |
| 键盘快捷键 | 无（Enter 提交已支持） | 🟡 中 |
| 拖拽到窗口 | 未接（Wails 支持 `OnFileDrop`） | 🟠 高 |
| 首启动引导 | 无：不装模型直接点开始会失败 | 🟠 高 |
| 深色/浅色、中英 | 完整 | — |

## 7. 优先级（按「卡住普通用户」排序）

| P | 问题 | 为什么排这个位置 |
|---|---|---|
| **P0** | A6 参数页不生效 | 界面在说谎，比缺失更坏 |
| **P0** | A4 输出目录不能选 | 用户找不到自己的产物，等于白跑 |
| **P0** | A3 不能浏览/拖入，只能手打路径 | 第一道门槛就劝退 |
| **P0** | B1 多文件前端未接 | 后端白做 |
| **P1** | A9/E3 一键打开产物目录 | 跑完找不到东西 |
| **P1** | A5/D4 选模型 | 决定质量的核心开关 |
| **P1** | A8 取消运行 | 跑错了只能杀进程 |
| **P1** | C3 卸载模型 | 磁盘无法回收 |
| **P2** | E2 打开单集看逐字稿 | 资料库才有意义 |
| **P2** | 首启动引导、系统通知、错误日志入口 | 降低挫败感 |
| **P3** | E4/E5 删除/重跑、快捷键 | 便利性 |

## 8. 审计结论

- **后端能力普遍超前于界面**：队列、参数、取消、安装都已有可调用实现，但用户看不到或用不上。
- **最严重的问题不是「没做」，而是「界面承诺了没做的事」**：参数页写着「改过的项会写进产物元数据」，
  而 `NewTask` 提交的是空参数。这类问题会直接摧毁信任。
- 我此前把「端点通 + CI 绿 + 截图能看」当成完成，这是**判据选错**，不是执行不到位。
  正确的判据是：审计表里每一行的「痛感」不得为 🔴。
