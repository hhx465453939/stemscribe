# 能力差距分析 · Stemscribe vs 日常多软件工作流

> 方法：① 用真实素材实测（`E:\VideoDownload\战锤40k 世界观 众生录`，30 分钟中文视频，自带 B 站 `.ai-zh.srt` 作参考基线）；
> ② 从 GitHub 源码/README 拆解三个目标项目的实际功能（UVR5 `Anjok07/ultimatevocalremovergui`、
> Buzz `chidiwilliams/buzz`、WhisperDesktop `Const-me/Whisper`）。
> 只写实测与已核实的事实，不写推测。

## 1. 实测基线（这是最重要的数据）

素材：`【战锤40K世界观01】…认识黑暗银河.mp4`，**29:57**，AAC 48kHz 立体声。
配置：`whisper-tiny`（唯一已装模型）+ vulkan 运行时 + `-l zh`。

| 指标 | 实测值 |
|---|---|
| 引擎总耗时 | **104.8 s**（RTF ≈ **0.058**） |
| 产物段数 | 163 |
| 显存 | RTX 3060 12 GB，运行前空闲 9.5 GB |

**质量对照（同一段音频）**

| 参考（B 站 AI 字幕） | 我们（tiny） | 判定 |
|---|---|---|
| 先给你介绍一个宇宙 | 先给你介绍一个宇宙在这个宇宙里 | 分段过粗（三句并一段） |
| 在这个宇宙里 | （并入上一段） | 缺句级切分 |
| 人类统治着100多万颗星球 | 人类**通知**这一百多万**科**星球 | 字词错（统治→通知，颗→科） |
| — | 金色王座上身体早已**哭味** | 枯槁 → 哭味 |
| — | 人类的**非传**要穿过… | 飞船 → 非传 |
| — | 才能在新**性**之间穿**醒** | 星系 → 新性；穿行 → 穿醒 |
| — | 人类最**惊瑞**的战士 | 精锐 → 惊瑞 |

**结论**：`tiny` 对中文**不可用**，不是后处理能救的程度。两个独立根因：
1. **模型容量**（决定性）：tiny → medium/large 是数量级差别；
2. **没有句级切分**：`max_len`（`-ml`）默认 0 = 不限，导致长句粘连；参考字幕是短句。

### 1.1 medium 复核（2026-11-26）

同一集 `01`（29:57）用 `whisper-medium` + vulkan 重跑，其余条件不变：

| 指标 | tiny（align 修复后） | medium（实测） |
|---|---|---|
| 引擎耗时 | 104.8 s | **199.13 s（RTF 0.111）** |
| 段数 | 283 | **334** |
| 行宽 median / p90 / max | 32 / 39 / 40 | **23 / 38 / 40**（两者超 40 字均为 0） |
| 粗估 CER（vs B 站参考） | 33.98% | **7.12%**（LCS 近似，偏高上界） |
| 抽检旧错词 | `通知 非传 新性 惊瑞` 仍在 | `统治` 4、`飞船` 2、`星系` 1、`精锐` 1，旧错形均 0 |

> 对照说明：两行都是 align 修复后的产物（修复前的 tiny 是 163 段 / max 328，见 §1）。
> CER 比对用同一集、同一参考字幕，只换模型。

> CER 用 `difflib` 的 LCS 匹配块计算，属偏高上界；可信 CER 由 CHG-0015 M4 的脚本产出。
> 30 分钟 3.3 分钟出稿，满足 PRD N-04（≤6 分钟）。

### 1.2 large-v3 复核（2026-11-26，强制分离后）

同一集 `01`（29:57），本 CHG 的新主链路：demux → **UVR5 分离** → 用 `vocals16k.wav` 转写，
`whisper-large-v3`（3,095,033,483 B，sha256 实测）· vulkan 1.9.5。

| 指标 | medium（CHG-0014） | large-v3（本轮） |
|---|---|---|
| 转写输入 | 原声 16k | **分离后人声** |
| 引擎耗时 | 199.13 s（RTF 0.111） | **287.19 s（RTF 0.160）** |
| 分离耗时 | 无 | **18 min 58 s**（CPU，RTF 0.63） |
| 段数 | 334 | 273 |
| 端到端 | ≈3 min 19 s | **≈23 min 48 s** |
| CER vs 同集参考 | 7.12%（等长前缀粗估，偏高上界） | **6.42%（Levenshtein 真 CER）** |

> 度量不同不可直接相减：7.12% 是旧粗估上界，6.42% 是真编辑距离。结论只有一条：
> large-v3 + 先分离**没有变差**，且逐字稿来自纯人声轨。
> 表中 18 min 58 s 是 CPU 分离基线；CHG-0017 把分离切到 CUDA 后同素材降到 ~3 min 51 s（见 §2.1），
> 30 分钟一集的端到端由 ~24 分钟降到 ~9 分钟。分离仍是必选前置（ADR-037），不是跳过分离。

## 2. 功能对照（源码级事实）

### 2.1 Ultimate Vocal Remover 5（人声分离）

| 能力 | UVR 有 | 我们 | 差距 |
|---|---|---|---|
| MDX-Net / VR / Demucs v3/v4 三种架构 | ✅ | ✅ MDX-Net（`Kim_Vocal_2.onnx`，`audio-separator` 0.48.0，CUDA 12 onnxruntime；无 GPU 时 CPU 并显性标注） | VR/Demucs 未接（registry 可加，代码同一条路径） |
| 分轨输出：vocals / instrumental（2 轨）、drums/bass/other/vocals（4 轨） | ✅ | ✅ 2 轨：`vocals.wav` / `instrumental.wav`（+ 16 kHz `vocals16k.wav` 供 whisper） | 4 轨未接 |
| segment / window 大小（显存不够时的救命参数） | ✅ | ⚠️ `SeparateOptions.SegmentSecs` 只做参数占位，切割由 `audio-separator` 内部决定 | 未暴露 |
| Ensemble（多模型加权融合） | ✅ | ❌ | 缺 |
| 非 wav 输入依赖 ffmpeg | ✅ | ✅ 已有（demux 一次产出 44.1k 立体声 + 16k 单声道） | — |
| Rubber Band 变速/变调 | ✅ | ❌ | 缺（低优先） |

> 实测（2026-11-26，E5-2696 v3 18C/36T，CPU）：30 min 素材分离 **18 min 58 s**（RTF ≈0.63），
> 峰值 RSS ≈5.1 GB，不占显存。该时间是"每 15 s 一段 + 2 s 交叉淡化"的整段 CPU 推理，
> 换桌面 8 核会明显变慢；这是**必选前置**（ADR-037），不是可选项。
>
> 同一素材在 RTX 3060 上用 CUDA 12 onnxruntime（`onnxruntime-gpu 1.21.1`）重跑：**3 min 51 s**
> （231 s，RTF ≈0.13，**4.9×**），`nvidia-smi` 显存 2372 → 4617 MiB。120 s 短素材对照：
> CPU 76.3 s / CUDA 25.1 s（3.0×，短素材的启动开销占比更高）。

## 3. 结论：对一个「视频 → 好逐字稿」用户，原本卡住四件事（2026-11-26：前两件已落地）

按影响排序（不是按实现难度）：

| # | 缺口 | 影响 | 现状证据 |
|---|---|---|---|
| **1** | **可用的大模型没装**：`whisper-base/small/medium/large-v3` 的 sha256 都是 `tbd`，安装会被拒 | 直接决定成败。tiny 输出不可用 | ✅ **2026-11-26 已解决**：medium 实测 1,533,763,059 B / sha256 `6c14d5ad…6208`，安装成功；5 min 片段 RTF 0.118、输出简体通顺。base/small/large-v3 仍为 `tbd` |
| **2** | **句级切分缺失**：`max_len=0` | 一行几百字，无法当字幕读 | ✅ **已解决**：`align` 合并上限 `MaxMergedRunes=40`；同一集实测 max 328→40，超 40 字行 = 0 |
| **3** | **VAD 不可用**：whisper.cpp 需要 silero VAD 模型，registry 没有这类条目 | 有 BGM/静音时幻觉、重复 | `--vad` 被置灰并提示需模型 |
| **4** | **没有逐字稿查看器**：跑完只能打开文件夹看 md | 校对、定位、改错全在外部工具做 | 资料库只读列表 |

次要但明确（不阻塞出稿）：说话人识别（Buzz）、监听文件夹（Buzz）、YouTube 导入（Buzz）。（人声分离 2026-11-26 已落地，见 §2.1）

## 4. 计划（一次性立项，按序交付）

| 步 | 内容 | 验收 |
|---|---|---|
| A1 | ✅ **实测并回填 medium 的 sha256**（1.46 GB；实测体积与 registry `size` 一致） | 已完成 2026-11-26：registry 无 `tbd`，安装成功 |
