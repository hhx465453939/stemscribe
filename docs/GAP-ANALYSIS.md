# 能力差距分析 · Stemscribe vs 日常多软件工作流

> 方法：① 用真实素材实测（`E:\VideoDownload\战锤40k 世界观 众生录`，30 分钟中文视频，自带 B 站 `.ai-zh.srt` 作参考基线）；
> ② 从 GitHub 源码/README 拆解三个目标项目的实际功能（UVR5 `Anjok07/ultimatevocalremovergui`、
> Buzz `chidiwilliams/buzz`、WhisperDesktop `Const-me/Whisper`）。
> 只写实测与已核实的事实，不写推测。

## 1. 实测基线（这是最重要的数据）

素材：`【战锤40K世界观01】…认识黑暗银河.mp4`，**29:57**，AAC 48kHz 立体声。
配置：`whisper-tiny`（唯一已装模型）+ vulkan 运行时 + `-l zh`。

| 指标 | 实测值 |
|---|---|
| 引擎总耗时 | **104.8 s**（RTF ≈ **0.058**） |
| 产物段数 | 163 |
| 显存 | RTX 3060 12 GB，运行前空闲 9.5 GB |

**质量对照（同一段音频）**

| 参考（B 站 AI 字幕） | 我们（tiny） | 判定 |
|---|---|---|
| 先给你介绍一个宇宙 | 先给你介绍一个宇宙在这个宇宙里 | 分段过粗（三句并一段） |
| 在这个宇宙里 | （并入上一段） | 缺句级切分 |
| 人类统治着100多万颗星球 | 人类**通知**这一百多万**科**星球 | 字词错（统治→通知，颗→科） |
| — | 金色王座上身体早已**哭味** | 枯槁 → 哭味 |
| — | 人类的**非传**要穿过… | 飞船 → 非传 |
| — | 才能在新**性**之间穿**醒** | 星系 → 新性；穿行 → 穿醒 |
| — | 人类最**惊瑞**的战士 | 精锐 → 惊瑞 |

**结论**：`tiny` 对中文**不可用**，不是后处理能救的程度。两个独立根因：
1. **模型容量**（决定性）：tiny → medium/large 是数量级差别；
2. **没有句级切分**：`max_len`（`-ml`）默认 0 = 不限，导致长句粘连；参考字幕是短句。

## 2. 功能对照（源码级事实）

### 2.1 Ultimate Vocal Remover 5（人声分离）

| 能力 | UVR 有 | 我们 | 差距 |
|---|---|---|---|
| MDX-Net / VR / Demucs v3/v4 三种架构 | ✅ | ❌ `Separate()` 返回 `ErrNotImplemented` | **整块缺失** |
| 分轨输出：vocals / instrumental（2 轨）、drums/bass/other/vocals（4 轨） | ✅ | registry 已声明 `stems`，但无推理引擎 | 数据层就位，引擎缺 |
| segment / window 大小（显存不够时的救命参数） | ✅ | 只有 `segment_default_s`，无 window/overlap/aggregation | 缺 |
| Ensemble（多模型加权融合） | ✅ | ❌ | 缺 |
| 非 wav 输入依赖 ffmpeg | ✅ | ✅ 已有 | — |
| Rubber Band 变速/变调 | ✅ | ❌ | 缺（低优先） |

### 2.2 Buzz（批量转写工作流）

| 能力 | Buzz 有 | 我们 | 差距 |
|---|---|---|---|
| 多后端（whisper.cpp / faster-whisper / OpenAI API / HuggingFace） | ✅ | whisper.cpp ✅，其余无 | 缺（faster-whisper 对中文通常更好） |
| **先人声分离再转写**（噪声环境准确率） | ✅ | ❌ | 依赖 2.1 |
| **说话人识别（diarization）** | ✅ | ❌ | 缺 |
| 导出 TXT / SRT / VTT | ✅ | ✅ 且更多（md/csv/json/lrc） | **我们更强** |
| **逐字稿查看器：搜索 + 播放器 + 调速** | ✅ | ❌ 资料库只读列表 | **重大缺口** |
| **监听文件夹自动转写** | ✅ | ❌ | 缺 |
| YouTube 链接直接转写 | ✅ | ❌ resolve 仅本地文件 | 缺 |
| 实时麦克风转写 | ✅ | ❌ | 缺（本工作流不需要） |
| CLI | ✅ | ✅ 更强（含参数面） | — |
| 插件系统（AI 摘要、自动重排） | ✅ | ❌ | 缺（低优先） |

### 2.3 WhisperDesktop（推理性能参考）

| 能力 | 它有 | 我们 | 差距 |
|---|---|---|---|
| GPU 加速 | DirectCompute（D3D11） | vulkan ✅ / cuda12（无 CI 硬件，`tbd`）/ cpu | 已有，但 cuda12 未发布 |
| 相对速度（medium, 1080Ti） | 10.6× 实时 | medium 未测（模型未装） | 待实测 |
| 首次启动引导下载模型 | ✅ 推荐 `ggml-medium.bin` | 模型中心可装（sha256 未实测的会被拒） | 有，但多数条目标记 `tbd` |
| 采集侧 VAD | ✅（自研算法） | ❌ 需 silero VAD 模型，registry 无此条目 | 缺 |
| 自动语言检测 | ❌（它自己承认没有） | ✅ `-l auto` | **我们更强** |
| 批量/队列 | ❌ | ✅（CHG-0012） | **我们更强** |

## 3. 结论：对一个「视频 → 好逐字稿」用户，真正卡住的只有四件事

按影响排序（不是按实现难度）：

| # | 缺口 | 影响 | 现状证据 |
|---|---|---|---|
| **1** | **可用的大模型没装**：`whisper-base/small/medium/large-v3` 的 sha256 都是 `tbd`，安装会被拒 | 直接决定成败。tiny 输出不可用 | 实测字词错误率极高 |
| **2** | **句级切分缺失**：`max_len=0` | 一行几百字，无法当字幕读 | 参考字幕 3 秒一行，我们 15 秒一段 |
| **3** | **VAD 不可用**：whisper.cpp 需要 silero VAD 模型，registry 没有这类条目 | 有 BGM/静音时幻觉、重复 | `--vad` 被置灰并提示需模型 |
| **4** | **没有逐字稿查看器**：跑完只能打开文件夹看 md | 校对、定位、改错全在外部工具做 | 资料库只读列表 |

次要但明确（不阻塞出稿）：人声分离（UVR）、说话人识别（Buzz）、监听文件夹（Buzz）、YouTube 导入（Buzz）。

## 4. 计划（一次性立项，按序交付）

### 阶段 A · 让逐字稿可用（最高优先，本阶段做完才算「能日常用」）

| 步 | 内容 | 验收 |
|---|---|---|
| A1 | **实测并回填 medium 的 sha256**（1.46 GB，已在下；实测体积须与 registry `size` 一致） | registry 无 `tbd`，安装成功 |
| A2 | **句级切分**：UI/队列默认带 `max_len`（中文 ~30 字）+ `-sow`（按词切） | 输出行宽与参考字幕同量级 |
| A3 | **VAD**：新增 silero VAD 模型条目（`family: vad`）+ 实测 sha256 + 允许 `--vad` | 长静音段不再产生幻觉句 |
| A4 | **逐字稿查看器**：资料库点开单集 → 分段列表 + 音频播放跳转 + 搜索 | 能在软件内校对 |
| A5 | 质量回归：用本目录两集对比 `.ai-zh.srt`，记录字词错误率 | 明显优于 tiny 基线 |

### 阶段 B · 声音处理（UVR 能力）

| 步 | 内容 |
|---|---|
| B1 | 分离推理引擎（ONNX Runtime + STFT/iSTFT），先接 VR（2 轨，模型已 HEAD 验证 63,454,827 B） |
| B2 | 4 轨（Demucs）——需要可验证权重直链 |
| B3 | segment/window/overlap/aggregation 参数（显存吃紧时能救） |

### 阶段 C · 批量与来源

| 步 | 内容 |
|---|---|
| C1 | 监听文件夹（放进去就自动排队） |
| C2 | YouTube/Bilibili 链接导入（需 yt-dlp，属外置进程） |
| C3 | 说话人识别（diarization），需额外模型 |
