# CHG-0010 · PRD · Run Control & Live Progress

## 1. 用户问题（一句话）

点了「开始」以后，软件**没有任何反应**——用户无法判断它是否在工作。

## 2. 用户故事

| # | 故事 | 现在的行为 | 期望 |
|---|---|---|---|
| U-1 | 我选好视频，点「开始」，想知道它有没有开始跑 | 按钮无 `onClick`，零反馈 | 立刻出现进度区：「已启动 · test.mp4」 |
| U-2 | 跑了三分钟，我想知道跑到哪一步 | 无从得知 | 显示当前阶段（解封装/转写/对齐/导出）与已完成阶段数 |
| U-3 | 它失败了，我要知道为什么、下一步做什么 | 无提示 | 失败阶段 + 引擎原话 + 可行动建议 |
| U-4 | 它跑完了，我要产物 | 无提示 | segments 数 + 产物目录（可复制） |
| U-5 | 我关了窗口又打开，任务还在跑 | 状态全丢 | 自动接回当前运行状态 |
| U-6 | 我用 CLI，也想看同样的进度 | 已有输出，但与界面不一致 | 同一套事件源，输出不退化 |

## 3. 非目标

- 不做多任务并行、队列、优先级。
- 不做断点续跑的新机制（复用既有 checkpoint）。
- 不做润色、人声分离的真实推理（分别属 CHG-0004/CHG-0003）。
- 不重写主题与字典机制（沿用 CHG-0007）。

## 4. 成功判据

1. 单击后 500ms 内出现进度区，且按钮进入忙碌态、不可重复点击。
2. 进度与真实阶段一一对应；**不允许**计时器假进度。
3. 失败路径给出原因与建议，不是空白或永久转圈。
4. 浏览器与原生窗口行为一致（同一 `http.Handler`）。
5. CLI 输出不因抽取而退化。
6. `dist/` 立即可点开使用。

## 5. 度量

| 指标 | 目标 |
|---|---|
| 点击到首个可见反馈 | ≤ 500 ms |
| 进度阶段与 `pipeline` 事件偏差 | 0（同源） |
| 失败时无原因的比例 | 0 |
| 界面/CLI 阶段名一致性 | 100% |

## 6. 为什么现在做

CLI 链路已经跑通并验证过真实产字，推理能力不是瓶颈；缺的是**控制面**。
控制面缺失会把「能用」变成「看起来坏了」，这是当前最高性价比的修复。
