# PRD · Stemscribe v0.1

> 本文定义**产品面**（谁用、为什么用、怎么用、什么样算好）。技术实现见 `docs/ARCHITECTURE.md`，
> 验收判据见 `tasks/CHG-0001/SPEC.md` §6。

---

## 1. 一句话定位

**Stemscribe 把一段视频变成一份可检索、可对话、可复现的文字档案——全程在你自己的显卡上跑。**

英文：*Turn any video into an archival-grade transcript on your own GPU.*

## 2. 用户与场景

### 2.1 主用户

| 用户 | 现在的做法 | 痛的地方 |
|---|---|---|
| **内容研究者**（主） | 手动下视频 → UVR 提人声 → Buzz 转写 → 贴给 GPT 润色 → 复制到笔记 | 200 集要重复 200 次；润色结果散落在聊天记录里 |
| **自媒体/剪辑者** | 同上，更关心字幕文件 | 时间轴不准、字幕要再手工调 |
| **开发者** | 想要「能喂给 agent 的本地知识库」 | 没有结构化产物，agent 无法引用带时间戳的原话 |

### 2.2 三个必须成立的场景

**S1 · 单集快速建档（3 分钟目标）**
> 「我下班路上刷到一个 42 分钟的行业访谈，想把它的要点带走。」
> 拖入链接 → 点「开始」→ 去泡咖啡 → 回来看到：大纲 8 条 + 关键结论 12 条 + 逐字稿（带时间戳）+ 可直接复制的「上下文包」。
> 断言：**全程零次手工选文件、零次打开别的软件。**

**S2 · UP 主批量归档（无人值守）**
> 「这个 UP 主 180 集，我想全建一遍，晚上挂着跑。」
> 粘贴 UP 主空间链接 → 勾选集数 → 设定「分离=人声优先 / 转写=medium / 润色=开」→ 排队。
> 第二天看板：成功 171、失败 9（附失败原因分类：下载 403 / 音频损坏 / 转写超时）。
> 断言：**失败项可单条重试，已完成的不会重跑。**

**S3 · 跟 agent 讨论内容（差异化场景）**
> 「把这份档案给我的 Claude/Codex 用。」
> 客户端内一键「注册到本地 MCP」→ agent 侧出现 `stemscribe` 工具 → 问「第 3 集里他说的那个反例是什么？」
> agent 返回带时间戳的原话 + 上下文。
> 断言：**agent 引用的是真实转写片段，不是模型幻觉。**

### 2.3 明确不服务的场景

- 实时会议转写（无此需求，架构不做流式麦克风采集）
- 多语言同传字幕（v0.1 只做单语转写 + 目标语言润色）
- 团队共享（v0.1 单机单用户，无账号）

## 3. 功能需求

### P0 · v0.1 必须都有（缺任一条不能叫 v0.1）

| ID | 需求 | 说明 |
|---|---|---|
| F-01 | 视频获取 | 支持 B 站单集 / 多 P / 合集 / UP 主空间批量；也支持本地视频文件拖入 |
| F-02 | 音轨提取 | 统一转 44.1 kHz 立体声 WAV（分离用）+ 16 kHz 单声道（转写用），由 ffmpeg 完成 |
| F-03 | 人声/伴奏分离 | MDX-Net ONNX 系列模型；可只保留 vocals 也可保留双轨；可选跳过分离直接转写 |
| F-04 | 语音转写 | whisper.cpp GGML/GGUF，支持 tiny→large-v3 与量化变体；输出段级时间戳与置信度 |
| F-05 | 字幕导出 | `.srt` / `.vtt` / `.md`（带时间戳锚点） |
| F-06 | LLM 润色（可选开关） | 逐字稿规整、标点分段、术语保留、生成大纲与要点；提示词可编辑可存版本 |
| F-07 | Provider 配置 | 填 base_url + api_key → 点「刷新」拉模型列表；每个模型可独立配置参数（见 3.3 大表） |
| F-08 | 模型与运行时管理 | 「模型中心」显示：已装/可装/下载中；支持下载、校验、删除、指定镜像源；显示磁盘占用与所需显存 |
| F-09 | 工作目录 | 首次启动让用户选 workdir（默认 `%USERPROFILE%\Stemscribe`）；模型/运行时/产物全在此目录，可整目录迁移 |
| F-10 | 任务看板 | 队列、运行中、成功、失败（可重试）；显示阶段进度（下载 x% → 分离 x% → 转写 x/总段 → 润色） |
| F-11 | 产物浏览 | 单集页：播放器（跟随时间轴跳转）、逐字稿、润色稿、元数据（模型/参数/耗时） |
| F-12 | Provenance | 每份产物记录：引擎版本、模型 ID + sha256 前 12 位、参数快照、提示词 hash、GPU 型号、耗时 |
| F-13 | 脱离网络可用 | 模型装好后，除「润色」与「在线下载」外全流程断网可跑 |
| F-14 | 崩溃可恢复 | 异常退出后重启，未完成任务从最近 checkpoint 续跑，不从头开始 |

## 4. 交互流程

### 4.1 首次启动向导（4 步，可跳过）

```
① 选工作目录  →  ② 硬件自检（GPU/显存/磁盘/ffmpeg）  →  ③ 选模型档位  →  ④ （可选）配 LLM
```

- 硬件自检结果必须**说人话**：`RTX 3060 · 12 GB 显存 · 建议档位「均衡」(medium + q5_0)`，而不是报一堆 CUDA 版本号。
- 磁盘预算直接给出：`基础套件约 2.4 GB（含分离模型 280 MB + whisper medium 1.5 GB + 运行时 620 MB）`。
- 档位三选一：**轻量**（小模型，4 GB 显存）· **均衡**（默认，6–8 GB）· **极致**（large-v3，12 GB+）。

### 4.2 主界面信息架构（4 个一级区）

```
┌ 左栏（240px） ┬ 主区 ────────────────────────┐
│ ▸ 新建任务    │  任务看板 / 单集详情 / 模型中心 / 设置  │
│ ▸ 资料库      │                                        │
│ ▸ 模型中心    │                                        │
│ ▸ 设置        │                                        │
└───────────────┴────────────────────────────────────────┘
```

**新增任务**只需一个输入框：
```
[ 粘贴链接或拖入文件...                          ]  [ 开始 ]
分离 ☑人声 转写 [medium ▾] 润色 ☑  [高级 ▾]
```
> 关键交互原则：默认参数能让 80% 的用户直接点「开始」，高级选项折叠不打扰。

### 4.3 运行中的可见性（这是信任的来源）

每个任务卡片显示**当前阶段 + 可解释进度**：

```
[▓▓▓▓▓▓▓░░░] 转写中 段 128/240 · 预计剩余 3m20s · GPU 8.1/12 GB · medium-q5_0
日志 ▸ 已跳过低置信度段 2 处（点击查看）
```

- 必须有「取消」和「跳过当前阶段」（例如分离太慢想直接转写原始音轨）。
- GPU 显存条常驻，超预算时提前告警而不是 OOM 后报错。

### 4.4 单集详情页

```
[播放器 · 波形图，可点击跳转]
────────────────────────────────
逐字稿 | 润色稿 | 字幕 | 元数据
00:01:23  他说这个方案的边界是……
00:01:41  （低置信度）……标记为黄色，可点击微调
```

## 5. LLM Provider 参数面（F-07 的完整定义，必须全部可见可改）

| 分组 | 字段 | 类型 | 默认 | 备注 |
|---|---|---|---|---|
| 连接 | `base_url` | string | — | 支持 `http://localhost:11434/v1` 等本地端点 |
| 连接 | `api_key` | secret | — | DPAPI 加密存储；本地端点可留空 |
| 连接 | `extra_headers` | kv[] | {} | 兼容 one-api / OpenRouter 的 `HTTP-Referer` 等 |
| 连接 | `timeout_s` / `max_retries` | int | 120 / 2 | 长文润色需更大超时 |
| 模型 | `model_id` | string | — | 从「刷新」得到的列表里选，也可手填 |
| 能力 | `context_window` | int | 自动 | 内置能力库 → 手改覆盖；UI 显示为 `200k / 1M` |
| 能力 | `max_output_tokens` | int | 4096 | 受 provider 上限约束 |
| 能力 | `vision` | bool | 自动 | 多模态（本产品 v0.1 未用，但需可见以免误判） |
| 能力 | `tools` / `function_call` | bool | 自动 | 同上，为 MCP/agent 阶段预留 |
| 能力 | `reasoning` | enum + budget | auto | `off/low/medium/high` 或显式 token 预算（Anthropic `budget_tokens`） |
| 能力 | `streaming` | bool | true | 关掉便于一次性校验 JSON |
| 采样 | `temperature` / `top_p` / `top_k` / `seed` / `stop` | num | 0.3 / 1.0 / auto / — | `top_k` 仅部分 provider 支持，不支持时灰显并说明 |
| 采样 | `presence_penalty` / `frequency_penalty` | num | 0 | 同上按 provider 能力灰显 |
| 输出 | `response_format` | enum | text | `text` / `json_object`（结构化大纲用） |

**灰度规则**：provider 不支持的能力字段必须**置灰 + 悬浮说明「该端点不支持」**，而不是隐藏或静默忽略——用户要能看见「我买到的模型到底有什么」。

## 6. 提示词（F-06）

内置 4 个可编辑模板，存为带版本的文件（`prompts/<id>@<hash>.md`）：

| 模板 | 用途 | 关键约束 |
|---|---|---|
| `clean-transcript` | 逐字稿规整：去口癖、补标点、分段 | **禁止改写事实、禁止合并不同时间戳的句子** |
| `outline-summary` | 大纲 + 要点 | 每条要点必须回链时间戳 |
| `term-glossary` | 抽取术语表（中英对照） | 保留原文拼写 |
| `qa-prep` | 生成「可被提问」的 10 个问题 | 用于后续与 agent 讨论 |

> 防幻觉硬约束（写进提示词 + 后置校验）：润色产物必须保留时间戳锚点；如 LLM 返回丢失锚点，则该段回退为原文并标记 `degraded`。

## 7. 非功能需求

| ID | 指标 | 目标值 |
|---|---|---|
| N-01 | 首次可用时间（已下载模型后） | ≤ 5 s 到可操作界面 |
| N-02 | 安装包体积（不含模型） | ≤ 40 MB portable zip |
| N-03 | 空闲内存占用 | ≤ 250 MB |
| N-04 | 30 分钟音频（medium 模型，3060） | 转写 ≤ 6 分钟；分离 ≤ 3 分钟 |
| N-05 | 隐私 | 音视频字节零外发；仅润色阶段外发**文本**，且必须显式开启 |
| N-06 | 可访问性 | 全键盘可达；对比度 ≥ 4.5:1；支持 125%/150% DPI |
| N-07 | 国际化 | UI 中/英双语，文案集中管理，不硬编码 |
| N-08 | 崩溃率 | 单次运行 8 小时内无未捕获崩溃；崩溃必须落 JSON 报告到 `logs/` |

## 8. 产品边界（明确拒绝的需求）

| 需求 | 拒绝理由 |
|---|---|
| 「帮我把视频传到你们的服务器转写」 | 违背本地优先定位 |
| 「内置 API Key 让我直接用」 | 成本与合规不可控 |
| 「支持 4K 视频剪辑」 | 不是编辑器 |
| 「自动搬运到 B 站」 | 版权与合规风险 |
| 「支持手机端」 | v0.1 不做，架构留 API 位 |

## 9. 验收演示脚本（人肉可复现）

1. 全新 Windows 机 → 装 `Stemscribe-0.1.0-setup.exe`
2. 首次向导：选 `D:\Stemscribe`，看到硬件自检显示「RTX 3060 12 GB · 建议均衡档」
3. 模型中心点「安装基础套件」→ 进度条跑到 100% → 显示三件套已校验（sha256 绿勾）
4. 粘贴一条 B 站链接 → 点「开始」→ 看板依次出现 下载 → 分离 → 转写 → 润色 四段进度
5. 完成后打开单集页：点逐字稿任一句 → 播放器跳到对应秒数
6. 点「导出」→ 得到 `meta.json / transcript.json / transcript.srt / polished.md`
7. 设置里换成本地 Ollama 端点 → 点「刷新」→ 看到 `qwen2.5:14b` → 改 `context_window` 为 131072 → 重跑润色成功
8. 拔网线 → 再跑一集（关闭润色）→ 成功（证明本地可用）
9. 强杀进程 → 重启 → 任务自动续跑到完成（证明 checkpoint 有效）
