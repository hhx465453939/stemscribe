# CHG-0019 · PRD — 新建任务页暴露阶段 1 的模型与产物选择

## 1. 问题（owner 原话，2026-11-27）

> 新建任务的界面，没有对于音轨提取模型的选择，也没有选择输出产物的选择，
> 没有对于其他音轨是否保留的选项，模型所以你也没有体现出来decum的选择，还是原来的uvr5模型

> 两个阶段，一个是抽提音轨，一个是vocal转换text，第一个阶段你就没有给用户选择模型的机会

现象：新建任务页只有「转写模型」一个下拉，分离阶段固定用设置里的 UVR5；
Demucs 虽然已装、registry 里也有，但用户在任务级看不到、也选不到。
分离产物（伴奏/鼓/贝斯……）算出来全部留在磁盘，无法按任务决定保留哪些。

## 2. 用户与场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 转录用户 | 只想拿到逐字稿 | 不关心伴奏，默认只留人声即可省磁盘 |
| 二次创作用户 | 需要伴奏/鼓/贝斯 | 同一任务里选模型 + 勾选要留的轨 |
| 换模型的用户 | 从 UVR5 换到 Demucs 6s | 旧模型的产物不能继续留在目录里冒充本次产物 |

## 3. 需求

1. 新建任务页必须能选**分离模型**，选项来自 registry 已安装的 separator，
   文本要能区分模型族（名称 + 架构 + 轨数 + 非商用标记）。
2. 必须能选**输出音轨**；可选项跟随所选模型的声明集合；人声恒保留（转写依赖），
   且视觉上是「已勾选」，不是灰掉的空框。
3. 必须能选**转写模型**，并与分离模型在同一页明确区分（标签不能都叫「模型」）。
4. 未勾选的音轨在分离完成后删除；分离本身仍算出全部轨（上游没有单轨模式）。
5. 换模型/改保留集后 resume，必须重跑分离，不许复用旧产物。
6. 目录里上一模型遗留的 stem 文件必须被清掉；`full.wav` / `16k.wav` /
   `vocals16k.wav` 属于派生文件，永远不动。
7. 所有删除都要可审计：事件日志写 `kept=` / `dropped=` / `removed stale=`，
   meta 只记录真实存在且被保留的轨。
8. 中文/英文文案齐平；双主题可读。

## 4. 非目标

- 不做「只算人声」的引擎级优化（上游 audio-separator 无此模式）。
- 不在本 CHG 改模型中心（模型安装/选择已在 CHG-0018 落地）。
- 不改调度与并发策略。
