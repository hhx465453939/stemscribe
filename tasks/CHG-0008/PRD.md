# PRD · CHG-0008 · 运行参数控制面与后端兼容矩阵

> 上游需求来源：owner 会话指令 2026-11-18
> 「分离除了 vocal 还有 instrumental；whisper 的 input/output 语言也要用户选；把运行相关选项以符合本项目美学的形式标记出来，让用户随时可以选择或填写；cuda12/vulkan/cpu 这类兼容性要在应用内部做好 fallback，哪怕 AMD 卡用 3D 渲染去跑也要能用起来——这个才是最重要的。」

## 1. 问题与用户

| 用户 | 场景 | 现状的痛 |
|---|---|---|
| 中文播客/访谈用户（主） | 中文素材转写 | **语言参数不可见**：默认 `-l en`，中文素材会被当英文硬转，结果烂但用户不知道为什么 |
| 需要字幕/翻译的用户 | 外文素材要中文字幕或英文稿 | 不知道 `-tr` 存在（它是"翻译成英文"，不是"选输出语言"），只能自己二次翻译 |
| 要伴奏/要人声的人 | 分离后只留 instrumental 或只要 vocal | 分离开关只有一个，**stem 目标不可选**；Demucs 能给 4-stem，完全用不上 |
| AMD / Intel 显卡用户 | 想让显卡参与 | 后端写死按 NVIDIA 判断，**AMD 用户直接掉 CPU**，慢到不可用 |
| 追求质量的人 | 长音频要更准 | 束搜索、温度回退、上下文、VAD 阈值全不可调，只能吃默认 |
| 排查问题的人 | 结果不对想知道用了什么参数 | 参数不进 provenance，无法复现 |

真实需求不是"加几个开关"，而是：**把引擎真实能力翻译成用户能理解、能填、能复现的选项，并且让每种显卡都能真的跑起来。**

## 2. 目标

| # | 终态（可判定） |
|---|---|
| G-1 | whisper 的**全部可调参数**在 UI/CLI 可见可选，默认值等于二进制真实默认（可脚本比对） |
| G-2 | **输入语言**（识别）与**输出语言**（原文/英文）分开表达；`.en` 模型与非 en 语言冲突时必须前置拒绝并说明 |
| G-3 | 分离 **stem 目标**可选（vocals / instrumental / 双轨 / 4-stem），且选项按模型真实能力启用 |
| G-4 | 后端 **cuda12 → vulkan → cpu** 自动降级；AMD/Intel 走 Vulkan；降级原因显性可见且可锁定 |
| G-5 | 参数快照进 `meta.json`；改参数使依赖阶段失效（复用既有 params hash） |
| G-6 | 所有新选项中英双语，符合 `docs/UI-DESIGN.md`（暗色瑞士网格 × 单一光源） |

## 3. 非目标（本 CHG 明确不做）

| 不做 | 理由 |
|---|---|
| ❌ **分离推理引擎本体**（MDX/VR/Demucs 的 ONNX/PyTorch 执行） | 需要 ONNX Runtime CGO 绑定或 Python 运行时（~350 MB）+ STFT/iSTFT 数值实现，是独立工程。本 CHG 交付**能力声明 + 选项 + 请求管线 + 引擎接口**；推理实现交 CHG-0009，且未就绪时选项必须**禁用并说明**，不允许假装可用 |
| ❌ DirectML 后端 | whisper.cpp 无成熟 DirectML 后端。不做假承诺：矩阵里标注"上游不支持" |
| ❌ 字级时间戳 UI、卡拉OK | `-owts` 能力会暴露，但可视化不做 |
| ❌ 每参数实时校验器 | 只做范围/枚举校验与冲突检测，不做语义调参建议 |

## 4. 功能需求

### P0（本 CHG 必须全部满足）

| ID | 需求 | 说明 |
|---|---|---|
| F-01 | whisper 参数面 | 按语义分组暴露 `--help` 里的真实 flag，含默认值、范围、单位、说明 |
| F-02 | 语言双维度 | `input_language`（`-l`，含 `auto`）+ `detect_only`（`-dl`）+ `translate`（`-tr`）三个独立项 |
| F-03 | 模型语言能力校验 | `.en` 模型 + 非 en 语言 → 明确报错并给出可行动建议；`auto` + `.en` → 拒绝 |
| F-04 | 分离 stem 目标 | `vocals` / `instrumental` / `both` / `four_stem`，按模型声明的 stems 启用 |
| F-05 | registry 记录 stems | 每个分离模型声明 `stems: [vocals, instrumental]` 或 `[drums, bass, other, vocals]` |
| F-06 | 后端矩阵 | `cuda12 → vulkan → cpu`；AMD/Intel → `vulkan`；探测不到 GPU → `cpu` |
| F-07 | 降级可见 + 可锁 | 每次降级写事件并在 UI 显示原因；用户可锁定后端（锁定后不自动降级） |
| F-08 | 参数持久化 | 按任务保存到 `meta.json` 的 `provenance.params_snapshot` |
| F-09 | 冲突检测 | 互斥项前置拒绝（见 F-03、`-dl` 与 `-tr` 同开、VAD 开关但无 VAD 模型） |
| F-10 | CLI 等价物 | 每个 UI 选项都有对应 CLI flag，便于脚本与 CI |

### P1（结构预留）

- 参数预设（快速/均衡/最准）一键切换
- 4-stem 结果分别导出与试听
- 参数影响预估（速度/显存）

## 5. 交互（符合 UI-DESIGN 的形态）

**原则**：默认值必须让 80% 的人直接点开始；参数不藏在二级弹窗，而是"同一张网格式参数表"，左列语义名、中列取值、右列出处/默认。

```
任务面板（折叠态，默认）
  分离 ☑ 目标[人声 ▾]   识别语言[中文 ▾]   输出[原文 ▾]   质量[均衡 ▾]
  后端：cuda12（自动，Vulkan 可用）                        [展开高级]

展开高级 → 参数表（分组，等宽数值，原生 range/select）
  ┌ 语言 ────────────────────────────────
  │ 识别语言     [中文 zh      ▾]   默认 en   -l
  │ 仅探测语言   [ ]                默认 关   -dl
  │ 翻译成英文   [ ]                默认 关   -tr
  ├ 质量 ────────────────────────────────
  │ 束搜索       [5]    1–10        默认 5    -bs
  │ 候选数       [5]    1–10        默认 5    -bo
  │ 温度         [0.00] 0–1         默认 0    -tp
  │ 温度回退     [x]                默认 开   (无 -nf 即开启)
  ├ 分段 ────────────────────────────────
  │ 最大段长     [0]    0=不限      默认 0    -ml
  │ 上下文       [-1]   -1=auto     默认 -1   -mc
  └ 后端 ────────────────────────────────
    后端 [自动 ▾]  候选：cuda12 / vulkan / cpu   锁定后不自动降级
```

约束：
- 灰色只用于**不可用**（如引擎缺失、上游不支持），并给原因；不可用不等于隐藏
- 数值项用等宽字体、右对齐；单位后缀小号
- 每个参数悬浮/次行给 flag 名，方便贴到 issue

## 6. 验收演示脚本

1. 中文素材 + 默认参数 → 结果显示语言被识别为 en 且质量差（复现现状）
2. 把识别语言改为中文 → 结果明显改善；`meta.json` 记录 `input_language: zh`
3. 勾选"仅探测语言" → 只输出检测到的语言，不产逐字稿
4. 勾选"翻译成英文" → 输出英文；同时勾"仅探测" → 前置拒绝并说明互斥
5. 换成 `.en` 模型 + 中文 → 前置拒绝："该模型仅支持英文，请改用多语种模型"
6. 分离目标选 instrumental → 勾选框随模型能力变（Demucs 出现 4-stem 选项）
7. 拔掉 CUDA 运行时目录 → 自动落 vulkan；再删 vulkan → 落 cpu；每步原因可见
8. 锁定 cpu → 有 N 卡也不切回
9. 改束搜索 5→1 → 转写阶段重跑（其它阶段不重跑）
10. 切 EN 界面 → 所有新参数标签/说明为英文

## 7. 边界

| 不做 | 理由 |
|---|---|
| 自动猜最佳参数 | 猜错比默认更糟，且不可复现 |
| 隐藏"危险"参数（温度、阈值） | 高级用户需要；折叠已足够 |
| 让用户直接写 ffmpeg 参数串 | 注入面，且破坏 provenance |
