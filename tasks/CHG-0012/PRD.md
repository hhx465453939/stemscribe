# CHG-0012 · PRD · Multi-file Intake & Run Queue

## 1. 用户问题（一句话）

我有一批视频要转写，现在只能一个一个说、一个一个等，人得一直守着。

## 2. 用户故事

| # | 故事 | 现在 | 期望 |
|---|---|---|---|
| U-1 | 我拖进来 5 个 mp4 | 拖入无效 | 5 个都进列表，按拖入顺序 |
| U-2 | 我点「浏览」，想一次选多个 | 只能填字符串 | 系统文件对话框可多选 |
| U-3 | 我点开始，想它自己跑完 5 个 | 要手动点 5 次 | 自动串行跑完 |
| U-4 | 第 2 个文件损坏 | 整轮停住 | 标记失败，继续第 3 个 |
| U-5 | 我排错了，想撤掉还没开始的那个 | 无从下手 | 列表项可移除 |
| U-6 | 我刷新了页面 | 队列没了 | 队列还在，进度接着显示 |

## 3. 非目标

- 不做并发推理（一台 GPU 并行只会互相抢显存）。
- 不做暂停/恢复、断点续跑的新机制。
- 不做浏览器端大文件上传。

## 4. 成功判据

1. 一次可加入 ≥2 个文件，顺序稳定。
2. 前一个结束后，下一个**自动**开始，无需人工干预。
3. 单项失败不影响后续。
4. 队列状态在后端，刷新不丢。
5. 移除只对未开始项生效。
6. 原生窗口的浏览/拖入返回真实绝对路径；浏览器明确说明不支持的原因。

## 5. 度量

| 指标 | 目标 |
|---|---|
| 相邻两个任务的衔接空档 | ≤ 2 s（不含推理本身耗时） |
| 坏文件导致整队停止的次数 | 0 |
| 刷新后队列丢失次数 | 0 |
